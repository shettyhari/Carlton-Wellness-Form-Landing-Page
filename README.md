# Carlton Wellness: Franchise Landing Page

Landing page for the Carlton Wellness franchise, with a two-step lead form and a backend that validates enquiries.

## Project structure

```
carlton-wellness-landingPage/
├── api/                Vercel serverless entry point (routes /api/* to the backend)
├── backend/            Lead API (Node.js + Express) that validates form submissions
├── database/           Left for the developer: lead fields the database needs to store
├── deploy/             Build script, PM2 process file, Nginx example, deployment guide
├── frontend/           Landing page (static HTML, config, images)
├── release/            Ready-to-upload copies, generated by `npm run build`
│   ├── backend/
│   └── frontend/
├── .gitignore
├── package.json        Root scripts (dev, build, test)
├── vercel.json         Vercel settings (static frontend + API function)
└── README.md
```

## Run locally

Requires Node.js 22.

```bash
npm run install:backend
npm run dev
```

Open http://localhost:4000. The backend serves the landing page and receives the form at `/api/leads`.

## How the lead form works

1. A visitor fills in step 1 (name, phone, email, city) and step 2 (capital contribution range, timeline, business background) in `frontend/index.html`.
2. The page sends the details to `POST /api/leads`.
3. The backend checks the name, phone and email, filters spam (hidden honeypot field, max 10 submissions per IP per 10 minutes) and passes the lead to `saveLead()` in `backend/src/leadStore.js`.
4. The visitor sees the thank-you screen.

**Database: not connected yet.** `saveLead()` only writes the lead to the server log. The developer connects the database there; see `database/README.md` for the fields.

Other endpoints: `GET /api/health` reports that the API is up.

## Configuration

Copy `backend/.env.example` to `backend/.env` and edit it. Key settings:

| Setting | Purpose |
|---|---|
| `PORT` | Port the backend listens on (default 4000) |
| `SERVE_FRONTEND` | `true` to serve the page from the backend, `false` when Nginx or cPanel serves it |
| `CORS_ORIGINS` | Only if the page and API are on different domains |
| `META_PIXEL_ID` | Meta Pixel ID, used when the backend serves the page |

`frontend/config.js` sends leads to `/api/leads` by default, which works on Vercel and on the Node.js server. If the page is hosted on its own, set `formEndpoint` to the backend's full URL. Set `metaPixelId` there too.

## Scripts (from the repo root)

| Command | What it does |
|---|---|
| `npm run install:backend` | Installs backend dependencies |
| `npm run dev` | Runs the backend with auto-reload |
| `npm start` | Runs the backend |
| `npm test` | Runs the API tests |
| `npm run build` | Refreshes `release/frontend` and `release/backend` |

See `deploy/README.md` for deployment.
